## Additional pinned Bun notice evidence

- Bun node-fallback closure: source lock copied byte-for-byte from https://github.com/oven-sh/bun/blob/0d9b296af33f2b851fcbf4df3e9ec89751734ba4/src/node-fallbacks/bun.lock. `polyfill-fallback-closure.txt` contains each exact package-version/integrity record in the runtime dependency closure, with available license files or README license sections from the verified npm tarball before metadata fallback; the SHA-512 integrity values printed with each entry match that lock. The closure includes the roots bundled by build-fallbacks.ts and their dependency closure, excluding build-only `esbuild` and `react-refresh`.
- libarchive per-file headers: `scripts/generate-libarchive-header-notices.ts` collects every distinct leading comment block containing a legal notice from the 123 unconditional source files listed by pinned `scripts/build/deps/libarchive.ts`, removing trailing whitespace; revision-id-only blocks are skipped while scanning continues to subsequent leading blocks. Source files are from libarchive commit `ded82291ab41d5e355831b96b0e1ff49e24d8939`; the pinned list is platform independent, and Windows-only additions are not compiled for the macOS release target. The complete `libarchive.txt` terms remain included.
- Hoehrmann UTF-8 decoder: `hoehrmann-utf8-dfa.txt` reproduces the copyright, MIT condition, and disclaimer shown at https://bjoern.hoehrmann.de/utf-8/decoder/dfa/. It applies to the identified DFA tables/decoder implementations.
- libbase64 and stream-browserify are stale inventory entries for this pin. Bun's root LICENSE.md lists them, but the pinned build inputs do not establish either as compiled/embedded: `scripts/build/deps` has no libbase64 dependency; the node-fallback lock and build-fallbacks.ts contain no stream-browserify package/input. The actual fallback is `readable-stream@4.7.0`, whose exact package notice is included. No revisions are inferable for the stale entries.
- When an exact-version fallback tarball has no license file, its README license section is included verbatim before considering package metadata and generic terms. This supplies the notices for `asn1.js@4.10.1`, `brorand@1.1.0`, `des.js@1.1.0`, `elliptic@6.6.1`, `hash.js@1.1.7`, `hmac-drbg@1.0.1`, `miller-rabin@4.0.1`, and `minimalistic-crypto-utils@1.0.1`. `constants-browserify@1.0.0` is covered by its README notice in the root polyfill license file.
